## Conventional Commits

**feat:** (Feature) – Adding new features and functionality.
_Example: feat: add user registration endpoint_

**fix:** (Bug Fix) – Fixing a bug.
_Example: fix: resolve null pointer exception in media search_

**chore:** (Chore) – Routine tasks such as updating dependencies, 
settings, etc. Not seen by the user.
_Example: chore: update spring boot version to 3.2.0_

**refactor:** (Refactor) – Refactoring the code without adding new 
features or bugfixes.
_Example: refactor: extract token validation to separate service_

**docs:** (Documentation) – Changes in documentation 
(README, API docs, etc.).
_Example: docs: update API swagger documentation_

**test:** (Testing) – Adding or updating tests.
_Example: test: add unit tests for subscription service_


## Issue Creation

Issues (backlog) are created using the following convention:

**As:** \<user role>

**I want:** \<task explanation>

**So that:** \<a resulting effort>

**(Optional) Requirements:**

\<Req. 1>

\<Req. 2>

...

_Example:_

**As:** a user

**I want:** to have an ability to get to platforms where I can explore tracked content

**So that:** I can actually view the content
